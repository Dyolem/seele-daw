# ADR-008：提交只校验它写过的内容

- 状态：Accepted
- 日期：2026-10-25
- 实施：与本文同一提交
- 取代：[ADR-001](./ADR-001-validate-each-commit-once.md) 中“每次提交做一次全量校验”

## Context

ADR-001 让每次提交在投影上做一次全量不变量校验。全量校验随项目大小线性增长：在 16 轨、每轨
5,000 个音符的项目上，移动一个音符的 17 ms 里有 13 ms 是它。另有两处随内容大小增长：投影第一次
写一个分区时复制整个分区；查询索引在每次提交时把被写的分区复制一遍、重新排序。在只有一个
80,000 音符 Source 的项目上，移动一个音符要 43 ms。ADR-001 的两个重新评估条件都已出现。

## Decision

1. 不变量按规模分两类。编排——Track、Clip、MIDI Source、Device、Timeline 事件、Track 顺序，以及
   哪些分区存在——随 Track 与 Clip 的数量增长，每次提交都整体检查。内容——分区里的 Note 与
   CC64 事件——随音乐增长，只检查提交写过的部分：
   - 写过的 Note：是否落在 Source 内；
   - 写过记录的 CC64 分区：整体检查，因为同一 Tick 与 Channel 只能有一枚事件；
   - Source 记录被写过、或分区是新建的：这个 Source 的全部内容；
   - 插入的 ID：在同一张表的全部分区中唯一，每个分区从较小的一侧探查。
2. 前提是提交前的模型有效。凡是模型来自外部的地方——新建、加载、回滚之后——仍做全量校验。
3. 任何一项失败，就对同一个模型做全量校验并报告它的结果，所以诊断与全量校验完全相同。
4. 投影不再复制表或分区。分区按条目覆盖，迭代顺序与 Store 的 Map 经过同样写入后的顺序一致。
5. 查询不再维护一个随提交更新的索引。`session.query` 从 Snapshot 回答：按 ID 查询在按 ID 排序的
   分区里二分查找；范围查询用按分区数组记忆的索引（`WeakMap`），没被改过的分区在下一份
   Snapshot 中是同一个数组（ADR-007），于是沿用上次的索引。`QueryIndex` 及其
   prepare / stage / rollback 删除。

## Consequences

- 移动一个音符：16 × 5,000 从约 17 ms 降到约 0.04 ms，1 × 80,000 从约 43 ms 降到约 0.02 ms。
  提交的成本只随它写入的内容增长。
- 读 Snapshot 仍要复制并排序被写过的分区：80,000 个音符的分区约 8 ms，5,000 个约 0.5 ms。范围
  查询在分区改动后的第一次查询时再按起点排序一次。
- 新增一张表时，要决定它属于编排还是内容。内容表的每条关系都要说明从写过的记录出发如何检查：
  按记录、按分区，还是像 ID 唯一性那样跨分区。
- 如果某种写入会破坏一条没被检查到的关系，运行时不会发现。`written-model-invariants.spec`
  用 1,500 组随机变化序列，比较提交校验与全量校验的结果，有效与无效的序列各有数百组；新增
  关系时，要让生成器能写出破坏它的变化。

## Validation

- `written-model-invariants.spec`：两种校验对每组序列报告相同的违规。故意去掉四项检查中的
  任意一项（写过的 Source、写过的 Note、写过的 CC64 分区、插入 ID 的唯一性），它都会失败。
- 基准：`pnpm --filter @seele-daw/project-core bench`。2026-10-25 在开发机上：

  | 场景          | 移动一个音符 | 再读 Snapshot | 全量校验 |
  | ------------- | ------------ | ------------- | -------- |
  | 16 轨 × 5,000 | 约 0.04 ms   | 约 0.5 ms     | 约 13 ms |
  | 1 轨 × 80,000 | 约 0.02 ms   | 约 8 ms       | 约 13 ms |

- `pnpm check` 全部通过。

## Revisit Trigger

- 编排表变得很大（例如上万个 Clip），整体检查成为提交的主要成本：按写过的记录检查编排关系。
- 读 Snapshot 时排序大分区成为瓶颈：用写过的记录合并上一份 Snapshot 的分区，而不是重新排序。
  已触发，见 [ADR-010](./ADR-010-edits-inside-a-clip-reuse-untouched-notes.md)。
